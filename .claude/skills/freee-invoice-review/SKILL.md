# freee 請求書 事前確認・事後反映確認

ユーザーが freee で作成した請求書（画像）を送信する前に内容を確認し、送信後は freee API
で実際に反映されたことを検証する、2フェーズのレビュー フロー。

## フェーズ1: 送信前レビュー（画像を受け取ったら）

ユーザーが請求書のスクリーンショットを送ってきたら、以下を画像から読み取って確認する。

### Step 1: 内容の整合性チェック

- **金額**: 小計 + 消費税 = 請求金額 になっているか（消費税率と小計から逆算して検算）
- **登録番号**: `T` + 13桁の適格請求書発行事業者番号フォーマットになっているか
- **日付**: 入金期日が請求日より後になっているか。極端に短い/長い支払サイトでないか
- **請求書番号**: 連番になっているか（前回の番号を把握していれば比較）
- **件名**: 空欄の場合は指摘する（必須ではないが、後で検索しやすくするため推奨）
- **振込先**: 支店名・口座名義が読み取れる範囲で不自然でないか（実際の通帳との一致は
  ユーザー側の目視確認に委ねる）

### Step 2: 重複登録の懸念チェック（MCP突合）

`freee_get_current_company` で事業所IDを確認後、同じ取引先・近い金額・近い日付の請求書が
既に存在しないか確認する。

```
freee_api_get {
  "service": "invoice",
  "path": "/invoices",
  "query": {
    "company_id": <company_id>,
    "partner_ids": "<partner_id が分かれば>",
    "limit": 20
  }
}
```

partner_id が不明な場合は `partner_ids` を省略し、直近の請求書一覧を取得して目視で
重複がないか確認する。**同一の請求書番号・同一金額・同一請求日の既存請求書があれば、
二重登録の懸念として必ず報告する。**

### Step 3: 結果報告

```
## 請求書レビュー結果

- 金額整合性: OK / 要確認（詳細）
- 登録番号フォーマット: OK / 要確認
- 日付: OK / 要確認
- 重複懸念: なし / あり（該当請求書: ...）

→ 送信して問題なさそうです。 / この点だけ確認してから送信してください。
```

## フェーズ2: 送信後の反映確認

ユーザーが「送信した」「登録した」と報告してきたら、実際に freee 側へ反映されているかを
MCPで確認する。**ユーザーが既に登録済みと言っている場合、freee_api_post 等で自分から
新規作成・登録操作を行わない**（二重登録防止。あくまで確認のみ）。

### Step 1: 該当請求書を検索

請求書番号が分かっていれば直接検索:

```
freee_api_get {
  "service": "invoice",
  "path": "/invoices",
  "query": { "company_id": <company_id>, "invoice_number": "<invoice_number>" }
}
```

請求書番号が不明なら、取引先・金額・日付で絞り込んだ一覧から該当行を特定する。

### Step 2: 反映内容の確認

取得した請求書の `sending_status` / `payment_status` / `deal_status` /
`cancel_status` / `total_amount` を、フェーズ1でレビューした内容と突き合わせる:

- 件数が1件だけか（重複登録されていないか）
- 金額がフェーズ1で確認した内容と一致するか
- `deal_status` が `registered`（取引/仕訳登録済み）になっているか

### Step 3: 結果報告

```
## 反映確認結果

請求書番号 <invoice_number> が正しく1件だけ反映されています。
- 送付: <sending_status>
- 決済: <payment_status>
- 仕訳登録: <deal_status>
```

重複や不一致があれば、その旨を明確に報告し、freee Web画面での確認を促す
（このスキル自身では削除・修正操作は行わない）。

## 注意

- **このスキルは freee 側の請求書・仕訳を新規作成・変更しない**。読み取り専用の
  確認のみを行う（登録操作は必ずユーザー自身が freee Web 画面で行う）
- フェーズ1とフェーズ2は別ターンで実行されることが多い（ユーザーが画面を見せる →
  実際に登録する、の間に間隔が空く）。それぞれ独立して呼び出せるようにする
- 会計期間をまたぐ月次請求書（例: 大石運輸倉庫株式会社・業務委託料のような定期請求）
  は、過去数ヶ月分と同じパターン（金額・勘定科目・税区分）かどうかも参考情報として
  比較すると精度が上がる
- 一括ステータス監査（送付漏れ・入金期限超過等の全件チェック）は `freee-invoice-check`
  を使う。本スキルは「今まさに送ろうとしている1件」のピンポイント確認用
